# 灵眸改进调研：以"吾与点"为对标

> 2026-10-08 · Korm 指令"灵眸有很大改善空间，去学习吾与点"
> 状态：调研完成，三期方案待 CO 逐轮落地

## 一、吾与点是什么

- **全称**："吾与点"古籍智能整理平台（wyd.kvlab.org），北京大学数字人文研究中心 + 中文在线元引公司联合开发
- **定位**：不是 OCR 工具，是**古籍整理流水线**——图片文字识别 → 自动句读/标点 → 命名实体识别 →（v2）分词/关系抽取
- **关键指标**（官网公开）：
  - 句读：BERT 增量训练（10 亿字古汉语语料 + 7 亿字句读训练集），古文断句 94.9%、标点 90%+；API 5 万字/10 秒
  - NER：地理/年号/职官/著书等实体，同型语料 98.5%；先秦人名 87%/地名 82%；明清小说 80%
- **本质洞察**：用户要的不是"图上有什么字"，是"**能读的文本**"——识别只是入口，句读和实体标注才是交付物

## 二、对标出的差距（灵眸现状）

| 环节 | 吾与点 | 灵眸现状 |
|---|---|---|
| 识别 | 古籍专用 OCR | PP-OCRv6 通用（生僻字强，竖排/版面弱） |
| 句读标点 | ✅ 核心功能 | ❌ 无 |
| 实体标注 | ✅ 地名/年号/职官/人名 | ❌ 无 |
| 校对交互 | 平台级（按列/按页校对、切分校对） | 只读结果+复制 |
| 下游联动 | 平台内闭环 | ❌ 无 |

## 三、三期改进方案（落地路径）

### 一期：识别后处理——句读/标点（本地、离线）
- 依赖：**jiayan 0.0.21**（PyPI 在册，2026-10-08 验证可下载；纯本地古汉语 NLP：断句、标点、分词、词性）
- 面板加"句读"开关：OCR 结果 → jiayan 断句/标点 → 双栏对照（原文行 / 句读本）
- 行级编辑：低置信行（conf < 0.85）点击改字，改完同步全文
- 交付：识别文本从"字串"变"可读文本"——对齐吾与点核心体验

### 二期：实体标注 + 六月息独有联动（差异化打点）
- NER：jiayan 词性层起步，后续可评估 GujiBERT 微调模型
- **灵眸可以比吾与点更进一步的地方**：识别出的地名/年号/职官**一键跳六月息自己的工具书原书检索**（史为乐地名典/李崇智年号考/职官字典/CBDB 人物）——吾与点是平台，没有工具书层；六月息有。实体点击 → 自家原书页码，这是对方给不了的
- 反向也通：拖一张工具书页 → 识别 → 自动跑解析管线（年号考/地名典的 OCR 后处理就是这套）

### 三期：校对交互 + 管线直通
- 低置信可视化（色阶）、按行校对模式（参考如是古籍的按列/按页校对）
- 导出 jsonl 进 toolbooks 管线（OCR 产物直落 data/toolbooks，省手工搬运）
- 批量：多图队列（一本书拖进来排队识别）

## 四、风险与边界

- jiayan 是源码 tarball 包，Windows 编译依赖待验证（先 venv 试装再定）
- jiayan 句读模型面向**传世文本**（横排整理本），对 OCR 误字敏感——低置信行先校再句读，或句读结果保留对照
- 竖排识别是 PP-OCRv6 短板，吾与点 OCR 细节未公开——一期不动引擎，先补后处理

## 五、一句话定位

吾与点 = 识别+理解一体化的**平台**；灵眸的赢面 = 识别+理解+**自家工具书与史料库联动**的学术工作台一环。
