# 六月息插件化架构提案（v0 草案 · 2026-10-05）

> 起因：Korm《工作台搭建回顾》（公众号 F04287航行日志，2026-10-04）明确提出：
> "下一步是把这种功能改造成插件，让人自由选配""卸下来独立呈现，成为能够选配的零件，
> 最好可以兼容其他工作台。拆卸如果顺利进行，组装接口的设置加固大概也可计日而待了。"
> 本文档是"怎么拆"的技术方案，供拍板。

## 一、现状体检

app.py 约 2700+ 行、51 个路由，五大块：
| 块 | 后端 | 前端 | 耦合度 |
|---|---|---|---|
| CBDB 检索/亲属/社会关系/任职 | 大（Access 连接池+内存索引） | 8 tab 深交互 | 高（地图依赖其 geojson/nearest/轨迹） |
| Zotero 联动 | 中（local API 代理+附件路径兜底） | 读文献页 | 低 |
| Obsidian 桥 | 小（写笔记/足迹/知识库） | 各页分散调用 | 低（被多方依赖→留核心） |
| AI 通道 | 小（/api/ai/chat 代理） | AI 页+注入机制 | 低（被多方依赖→留核心） |
| 学术动态 feed | 中（arXiv/PubMed+缓存） | 面板 | 极低（最独立） |
| 史学工具六件 | 小（静态数据+检索） | 工具页 | 零（纯本地） |

## 二、拆分原则

1. **依赖单向**：插件 → 核心服务。插件之间不直接 import，通过核心暴露的服务函数互通。
2. **核心只留三样**：启动/插件加载器；共享服务（Obsidian 写入、Zotero 代理、AI 通道、CBDB 数据服务——地图要用）；静态入口模板。
3. **插件 = 一个文件夹**：
```
plugins/
  <plugin_id>/
    manifest.json     # 名字/版本/路由入口/nav 注入/依赖声明
    routes.py         # Flask Blueprint（相对导入 core_services）
    static/           # 自带 js/css（可选）
    data/             # 自带数据（可选，大数据仍走全局数据目录）
```
4. **装插件 = 丢文件夹**：loader 启动时扫描 plugins/，读 manifest，注册蓝图+注入 nav。装/卸 = 增删文件夹+重启。frozen（安装版）下同样成立——plugins/ 作为数据目录 PyInstaller 收集。

## 三、manifest.json 规范（草案）

```json
{
  "id": "acad-feed",
  "name": "学术动态",
  "version": "0.1",
  "requires": { "core_services": ["ai"] },
  "routes": "routes.py:bp",
  "nav": { "label": "学术动态", "icon": "🌐", "tab": "news" },
  "static": { "js": ["panel.js"], "css": [] }
}
```

## 四、试点顺序（按风险从低到高）

1. **学术动态 feed** —— 最独立，拆它验证"拆下来还能装回去"。风险≈0。
2. **史学工具六件** —— 纯本地数据+检索，第二个拆，验证"纯前端插件"形态。
3. **Zotero 读文献** —— 验证"依赖核心 Zotero 服务"的插件长什么样。
4. **CBDB 大插件（最后拆）** —— 最大最复杂，地图等依赖方改走核心 CBDB 数据服务。
   拆完它，"枢纽"理想的第一块基石（CBDB 插件可兼容其他工作台）就落地了。

## 五、风险与对策

- **frozen 模式动态 import**：PyInstaller onefile 下 importlib 动态加载 plugins 内的
  routes.py 不可行（源码不在文件系统）。对策：打包时把 plugins/ 作为 data 收集，
  loader 用 importlib.util.spec_from_file_location 从解压后路径加载——PyInstaller
  onefile 运行时 _MEIPASS 内可读到。需要 spike 验证（第一步就做）。
- **CBDB 与地图深度耦合**：geojson/nearest/人生轨迹三个端点被地图页调用。对策：拆 CBDB
  时这三个端点升格为"核心 CBDB 数据服务"，CBDB 插件本体只留检索 UI 与查询端点。
- **并行编辑冲突**：本仓库有另一会话的并行编辑史。对策：每个插件拆分独立 commit，
  小步快跑，拆完立即提交。
- **回归成本**：109 项测试要插件化后仍可跑（测试直接打 Flask test_client，蓝图注册后
  路由不变，理论上全绿不需要改测试——这是本方案最大的优点）。

## 六、今晚已落地的骨架（不改任何现有功能）

- `plugin_loader.py`：扫描 plugins/、读 manifest、注册蓝图、收集 nav 注入清单
- `plugins/_example/`：hello 示例插件（验证加载链路）
- app.py 只加两行：init 时调用 loader（现有路由一个不动）
