# 六月息插件开发指南

插件 = 一个文件夹（放进 `plugins/` 或用户插件目录），核心是一个 `manifest.json` 声明身份，`routes.py` 提供后端路由。

## 快速开始

1. 复制 `docs/plugin-template/` 为 `plugins/myplugin/`
2. 改 `manifest.json` 的 `id`/`name`/`desc`（id 必须小写字母开头，2-40 字符）
3. 重启 JuneXi —— 你的插件出现在「插件」管理页
4. 开发友好：改动 `routes.py` 只需重启；前端 assets 可强刷

## manifest.json 字段

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| id | ✓ | 唯一标识，小写字母/数字/中划线。同名用户插件覆盖内置 |
| name / desc / version | ✓ | 展示信息 |
| routes | ✓ | `"routes.py:bp"` —— 加载器 import 该文件并取 `bp`（flask.Blueprint）注册 |
| enabled | | 默认 true；开关由用户在管理页控制，写 `plugin-overrides.json` |
| nav | | `{tab,label,icon}` —— 注入顶部导航栏 tab 按钮（插在"插件"tab 前）。点击触发 `switchTab(tab)`；目标页面 div 可由核心模板提供或插件自行注入 DOM。禁用/卸载插件后 tab 自动消失 |
| assets | | `{css:[],js:[]}` —— 插件 `static/` 下的文件注入全站 |
| warmup | | `"warmup.py:run"` —— 启动时立即执行（预连接/预热） |
| permissions | | 声明权限：`network`（外链请求）/`files`（读写用户文件）/`none`。市场页显示给用户看 |
| settings | | 声明可由用户在插件管理页调整的参数（见下节「插件参数设置」）。声明后卡片出现 ⚙ 设置按钮 |

## 插件参数设置（Obsidian 式声明配置）

manifest 里声明字段，管理页自动生成设置面板，用户在 ⚙ 里改值，你的路由用 `get_plugin_config` 读取——不用自己写设置界面和存储。

### 声明（manifest.json）

```json
"settings": {
  "fields": [
    { "key": "n_refs", "type": "int", "label": "参考文献默认条数",
      "default": 100, "min": 10, "max": 200 },
    { "key": "endpoint", "type": "select", "label": "数据源",
      "default": "openalex",
      "options": [{ "value": "openalex", "label": "OpenAlex" },
                  { "value": "s2", "label": "Semantic Scholar" }] },
    { "key": "dry_run", "type": "bool", "label": "试运行（不写库）", "default": false },
    { "key": "api_key", "type": "password", "label": "API Key", "default": "" }
  ]
}
```

字段类型：`int`（min/max 裁剪）· `bool` · `select`（options 校验）· `text` · `password`（输入掩码）。只收声明过的 key，校验由核心完成。

### 读取（routes.py）

```python
def _cfg():
    try:
        import plugin_loader as pl
        return pl.get_plugin_config("myplugin")  # manifest 默认 + 用户覆盖的合并值
    except Exception:
        return {}

# 用法: 请求显式传参 > 配置默认 > 硬编码兜底
n = int(request.json.get("n") or _cfg().get("n_refs") or 50)
```

### 行为约定

- 存储在 `%LOCALAPPDATA%\JuneXi\plugin-config.json`（核心原子写，与用户插件目录并列），dev/安装版共享
- 用户值即时生效（下次请求即读），无需重启
- 请求参数显式传入时**优先于**配置默认——配置管"默认档位"，参数管"这次特殊"
- 列表 API 每项自动带 `has_settings`；未声明 settings 的插件卡片不出现 ⚙

参考实现：`plugins/litgraph/manifest.json`（3 个 int 档位数）+ `plugins/ai-agent/manifest.json`（2 个循环上限）。

## 后端约定

- 路由全部挂 `@bp.route(...)`，不要新建 Flask app
- 用 `_core("_log_activity")` 记足迹、`OBSIDIAN_VAULT` 等核心配置——**不要 `from app import ...`**（循环 import），惰性取保持解耦
- 插件之间不互相 import；跨插件数据走 HTTP 内部端点（如 CBDB 插件的 `/api/cbdb/_counts`）
- 路由命名建议 `/api/<插件id>/...`，避免撞车

## 导航注入（nav）

manifest 写 `"nav": {"tab": "mytab", "label": "我的插件", "icon": "🔬"}` 后，启动时前端自动把 tab 按钮插进导航栏（"插件"tab 之前）。两种页面模式：

1. **页面 DOM 在核心模板**（如读文献页）：核心提供 `<div id="mytab" class="page">`，nav 只负责 tab 按钮。适合与核心深度耦合的页面
2. **页面 DOM 插件自建**：用 assets 机制注入 JS，JS 在 DOMContentLoaded 时创建 `<div id="mytab" class="page">` 并填充内容。完全自治

插件被禁用或卸载后，tab 自动消失（loader 在收集 nav 前就跳过禁用插件）。

## 用户数据存储

插件的用户配置/缓存放 `%LOCALAPPDATA%\JuneXi\<插件id>\` 或 `%LOCALAPPDATA%\JuneXi\<插件id>.json`（参照 acad-feed 的 `acad_feed_sources.json` 自定义源模式）。不要写 `_MEIPASS` 安装目录（只读且升级即丢）。

## 打包发布

1. 文件夹打成 zip（zip 根 = 插件文件夹本身，内含 manifest.json）：
   ```powershell
   Compress-Archive -Path myplugin -DestinationPath myplugin.jxplugin
   ```
2. 本地测试：管理页「📦 安装新插件」→ 从本机安装
3. 发布：把 zip 传到你的 Release，算 SHA-256（`Get-FileHash myplugin.jxplugin -Algorithm SHA256`）
4. 向 junexi 仓库的 `plugins-registry.json` 提 PR，加一条目（id/name/version/desc/author/url/sha256/permissions），审核通过即上架市场

## 安全红线

- zip 安装有路径穿越防护，manifest 必须合法
- 别在插件里跑 `eval`/`exec` 外部输入；别静默外传用户数据——市场页会显示你的 permissions 声明，用户据此决定信不信

## 进阶: 给插件注册 AI 工具

插件可以让六月息的 AI 助手获得自己的能力——AI 页开启"agent 模式"后, 用户一句话, 模型自主决定调用哪些工具。

### 三步接入

```python
# plugins/your-plugin/routes.py
try:
    from agent_tools import tool

    @tool("my_search",                       # 工具名(英文, 全局唯一, 建议带插件前缀)
          "一句话说明这个工具做什么、何时用",   # 模型靠这句决定调不调
          params={"type": "object",
                  "properties": {"q": {"type": "string", "description": "检索词"}},
                  "required": ["q"]},
          action=None)                        # 可选: 执行成功后前端动作, 见下
    def _t_my_search(q):
        # 返回 dict; 出错返回 {"error": "..."} 即可, agent 会把错误反馈给模型
        return {"total": 0, "items": [...]}
except Exception:
    pass  # agent_tools 不存在时插件照常工作(纯功能不受影响)
```

1. `@tool(name, description, params, action)` 注册。description 写给模型看, 说清用途、参数、数据边界(如"收录不全")。
2. 数组/ID 类参数先过 `agent_tools.to_int_list()` 规范化。
3. `action` 非空时, 工具执行成功会生成前端动作(如把人物标到地图); 模板见 `agent_tools.derive_action` / cbdb 插件的 `show_persons_on_map`。

### 已知边界

- agent 循环单次最多 10 次工具调用, 写笔记类任务请引导模型"用已有结果, 别逐条补查"。
- 客户端类依赖(Zotero/Obsidian)未启动时, 返回诚实 `error`, 不要静默空结果。
- 注册幂等: 重复 import 不会重复注册, 放心依赖插件加载器。
